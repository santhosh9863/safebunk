# Phase 1.1 — focused classification error analysis

## Scope

This phase examines the original synthetic holdout for the **Electrical** versus
**Network / IT** confusion, adds targeted synthetic training examples, retrains,
and compares the candidate against the original baseline on the **same frozen
holdout**. No Flutter/NestJS code, report data, permissions, or production
thresholds were changed. The abstention threshold remains `0.20`.

The data is synthetic. These results are not production evidence.

## Baseline errors

The Phase 1 baseline (`v0.1.0`) made 16 errors on the 48-row holdout. Four were
Electrical <-> Network / IT confusions:

| Actual | Predicted | Confidence | Description |
| --- | --- | ---: | --- |
| Electrical | Network / IT | 0.159 | The ceiling fan in the library reading room makes a loud buzzing noise. |
| Electrical | Network / IT | 0.251 | The air conditioner in the server room trips the circuit breaker repeatedly. |
| Electrical | Network / IT | 0.160 | The wire from the projector is frayed and needs replacement. |
| Network / IT | Electrical | 0.144 | The attendance terminal near the main gate cannot reach the server. |

Observed pattern:

- Words such as **server**, **projector**, and **terminal** pulled Electrical
  descriptions toward Network / IT.
- The attendance-terminal example lacked unmistakable network vocabulary, so it
  moved toward Electrical.
- Three of the four focus errors scored below the `0.20` abstention threshold.
  The remaining one (`0.251`) would be predicted, so the error is not purely an
  abstention problem.

The full baseline report is in
`artifacts/category-classifier/v0.1.0/error_analysis.json`.

## Data changes

`data/phase1_1_additions.csv` adds **32 synthetic rows**: 16 Electrical and 16
Network / IT. They are contrastive examples around projectors, printers, server
rooms, fans, breakers, sockets, Wi-Fi, portals, and attendance devices.

- Every addition has `source=phase1_1_synthetic`.
- The Phase 1 file is unchanged.
- `data/synthetic_complaints_v2.csv` is generated by
  `scripts/build_phase1_1_dataset.py` and marks every row's source.
- The build checks that no new row creates a near-duplicate group crossing the
  frozen Phase 1 holdout.
- No holdout description was copied into the additions.

`data/synthetic_complaints_v2.csv` has 224 rows: 40 Electrical, 40 Network / IT,
and 24 in each other category. The deliberate oversampling is documented in
`data/synthetic_complaints_v2.metadata.json`.

## Evaluation protocol

1. Reconstruct the original 48-row Phase 1 test set from
   `data/synthetic_complaints.csv` with the same category-stratified grouped
   split (`test_fraction=0.25`, `random_state=42`).
2. Map those exact descriptions into the v2 dataset and freeze their row numbers
   as the holdout.
3. Train on the other 176 rows, including all 32 additions.
4. Reject the split if any near-duplicate group crosses the holdout.
5. Evaluate the baseline and candidate on the same 48 rows.

Reproduce with:

```powershell
.\.venv\Scripts\python.exe scripts\build_phase1_1_dataset.py
.\.venv\Scripts\python.exe scripts\train_phase1_1.py
.\.venv\Scripts\python.exe scripts\evaluate.py --model-dir artifacts\category-classifier\v0.2.0
.\.venv\Scripts\python.exe scripts\analyze_errors.py --model-dir artifacts\category-classifier\v0.2.0 --output artifacts\category-classifier\v0.2.0\error_analysis.json
```

## Interpretation limits

The candidate was trained on examples chosen after reviewing baseline holdout
errors. That makes this a **targeted synthetic regression benchmark**, not an
unbiased generalization estimate. The holdout was not used for training and no
holdout text or near-duplicate was copied, but the data additions were informed
by its error patterns.

The holdout has only six rows per category, so one changed prediction moves a
per-class score substantially. The improvement supports keeping the candidate as
a reviewed experimental model; it does **not** show production readiness, real
campus accuracy, or that the model is safe for automatic category changes.
